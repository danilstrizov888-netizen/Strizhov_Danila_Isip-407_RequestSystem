Запись 2. Работа с Git (лабораторная №2)



\---



&#x20;  1. Задача



Получить шпаргалку по Git-workflow для учебного проекта, шаблон .gitignore

для Python и описание типичного конфликта слияния.



\---



&#x20;  2. Модель

&#x20; 

DeepSeek-V3 (веб-версия, chat.deepseek.com, DeepThink выключен)



\---



&#x20;  3. Промпт

&#x20; 

> Привет! Помоги с лабораторной работой по Git. Я новичок, делаю учебный

> проект на Python — систему учёта заявок. Репозиторий на GitHub.

> Объясни мне:

> 1) какой Git-workflow обычно используют в учебных проектах? Опиши

>    последовательность команд: создание ветки develop, коммиты, слияние в main.

> 2) предложи 5 осмысленных сообщений для коммитов (в формате Conventional

>    Commits: docs, chore, feat, fix).

> 3) дай шаблон .gitignore для Python-проекта (чтобы исключить venv, кэш,

>    служебные файлы IDE, локальные базы и секреты).

> 4) как выглядит типичный конфликт Git при слиянии и как его исправить?

> Пиши простым языком.



\---   

&#x20;  

&#x20;  4. Почему такой промпт

&#x20;

Написал простым языком, с указанием стека (Python) и формата (Conventional

Commits). Попросил описать конфликт — это отдельный пункт методички.



\---



&#x20;  5. Почему такая модель

&#x20; 

DeepSeek бесплатна, хорошо работает с техническими темами. Для Git-шпаргалки

хватает.



\---



&#x20;  6. Результат ИИ



DeepSeek выдала:

\- пошаговый Git-workflow (main + develop + feature-ветки);

\- 5 коммитов в формате Conventional Commits;

\- большой .gitignore для Python;

\- описание конфликта с маркерами и способами решения.



\---



&#x20;  7. Проверка

&#x20;

Сверил с методичкой:

\- workflow — соответствует (есть develop, слияние в main);

\- 5 коммитов — есть;

\- .gitignore — есть;

\- конфликт — описан.



Обнаружил проблемы:

\- DeepSeek предложила коммиты на русском — а это может ломать кодировку

&#x20; в Git Bash.

\- .gitignore слишком большой — для учебного проекта достаточно проще.

\- Конфликт описан теоретически, но я его не моделировал.



\---



&#x20;  8. Собственная доработка

&#x20; 

\- Коммиты написал на английском (docs: update README и т.д.).

\- .gitignore оставил свой, короткий (без ruff, mypy, coverage — они не нужны).

\- Конфликт разобрал теоретически, описал в отчёте.



\---



&#x20;  9. Вывод 



DeepSeek даёт качественные шпаргалки по Git, но предлагает избыточные вещи

(большой .gitignore, русские коммиты). Для учебного проекта надо упрощать.

Модель хорошо объясняет команды, но итоговый набор команд всё равно надо

проверять самостоятельно.
